# interplanet (toke port)

A command-line demo of the InterPlanet planet-time library and the LTX v2
planId, written in [toke](https://github.com/karwalski/toke). It is a demo
CLI, not a library: other toke code cannot import it, and it covers a subset
of the JavaScript reference (see Limitations).

## Toolchain (pinned)

| | |
|---|---|
| Compiler | `tkc` from karwalski/toke, revision `0b0bc4e501633de471af4d7413c248036f7ccf92` (`toke 3.0.0`, 2026-09-23) |
| Tested on | x86_64 Linux (Ubuntu 24.04), clang 18.1.3 |
| Not tested | macOS, Windows, other tkc revisions |

The source is written in the current (3.0.0) toke dialect: `==` for equality,
`mt` for matching `!` results, `.push` on arrays. Code in the older dialect
(`=` as equality, `|{Ok:..;Err:..}`) is rejected by 3.0.0 with E2002; that
older code and the IR/binary built from it have been removed.

## Build

```sh
./build.sh                    # clones karwalski/toke into .toolchain/, builds tkc at the pinned revision, builds ./interplanet
TKC=/path/to/tkc ./build.sh   # use an existing tkc (must be the pinned revision)
```

`build.sh` runs `tkc src/interplanet.tk --out interplanet`. The build output
(`interplanet`, `.toolchain/`) is not committed.

```
  Day fraction:   0.017755760829
  Local hour:     0.426138259907
  Year:           35
  Day in year:    554
  Period in week: 2
  Work period:    yes
  Work hour:      no
  Sol in year:    554
  Sols/year:      669
  MTC:            00:25
  Light (Earth):  209.342373 s
  Helio r:        1.416875711 AU
```

Commands: `time <planet> [--tz <hours>]`, `mtc`, `light <a> <b>`,
`distance <a> <b>`, `los <a> <b>`, `windows <a> <b> [--days <n>]`, `planets`,
`ltx <title> <name:role:location[:delay]>... [--quantum <min>] [--mode <mode>]`
and `planid <plan-json>`. Every command except `planid` takes
`--at <utc-ms>` to fix the instant (default: now).

## Verification

```
$ python3 verify.py
reference.json: 54 entries
plan-ids.json: v2 vectors checked; skipped (v3): v3-upgrade-delays, v3-key-order-insensitive, v3-amendment
686 checks, 0 failures
```

`verify.py` runs all 54 entries of `c/planet-time/fixtures/reference.json`
(9 bodies x 6 instants, generated by planet-time.js 1.9.0) through `time` and
`mtc` and compares hour/minute/second, day number, day fraction, local hour,
year, day in year, period in week, work period, work hour, sol in year, sols
per year, MTC, light travel time from Earth and heliocentric distance. It then
runs the six v2 vectors of `spec/golden/plan-ids.json` through `planid`, and
rebuilds `v2-createPlan-default` with `ltx`. It is not wired into CI.

## Limitations

- Demo CLI only; there is no importable toke module or published package.
- One source file. At the pinned revision, multi-file builds
  (`tkc a.tk b.tk`) do not link on Linux (tkc passes all module `.ll` paths to
  clang as a single argument), so the former planettime/ltx/cli modules were
  merged.
- LTX: only the frozen v2 planId (spec 4.3: imul31 over the UTF-16 code units
  of `JSON.stringify(plan)`). v3 planIds (SHA-256 over RFC 8785 JSON, spec 4.5)
  are not implemented and `planid` rejects v3 plans. No plan validation,
  iCalendar export, URL hash encoding, delay matrices or session state.
- `ltx` always uses the default segment template (PLAN_CONFIRM TX RX CAUCUS TX
  RX BUFFER). A node without an explicit `:delay` gets the rounded light time
  from the first node's location at the start instant. The start is the
  `--at` instant (or now) floored to the whole minute; the reference
  `createPlan` defaults to now plus 5 minutes.
- `planid` is not a JSON parser. It expects the exact `JSON.stringify` text of
  a v2 plan (compact, keys in insertion order) and finds the start date and
  node names by scanning for `"start":"` and `"name":"` keys. The host/node
  prefixes strip ASCII whitespace and upper-case ASCII only, so non-ASCII node
  names can give a different prefix than the reference (non-ASCII titles are
  fine; the hash itself handles full UTF-16).
- Planet time: no timezone zone IDs (AMT etc.), no Mars zone table, no
  `nextPlanetTime`, hourly schedules, lower-quartile light time or multi-location
  meeting finder. `--tz` offsets are in local planet hours as in the reference.
  `windows` scans in 15 minute steps like `findMeetingWindows`.
- Leap seconds are hard-coded through 2017-01-01 (TAI-UTC = 37 s), like the
  reference.
